## 1. 系统上下文

本系统从外部行情和财报来源采集数据，以 MySQL 保存证券主数据、财报、版本化行情、持久化计算任务和不可变结果，通过 Gin HTTP API 向 React 行情工作台及兼容客户端提供查询、扫描和回测能力。

`main.go` 是组合根，负责配置加载、数据库和适配器初始化、HTTP 服务、任务 Worker、行情调度以及优雅停机。组合根不承载业务规则。

运行时主要边界：

```text
外部数据源 ──> Broker Adapter ──> Application ──> Port ──> MySQL
                                      │
HTTP / Web ──> API Adapter ───────────┤
                                      └──> Market / Indicator / Strategy / Backtest
```

## 2. 分层与依赖方向

依赖方向固定为：

```text
api / infrastructure / pkg
              ↓
         application
              ↓
       port 与纯领域模块
```

- `internal/market`、`internal/indicator`、`internal/strategy`、`internal/backtest` 是纯领域/计算模块，不依赖 Gin、GORM、MySQL、HTTP 客户端或具体数据源。
- `internal/application` 编排用例、重试、取消、事务外流程和生命周期，只依赖领域对象与 `internal/port`。
- `internal/port` 定义应用真正需要隔离或替换的能力边界。
- `internal/infrastructure/mysql` 实现持久化端口。
- `pkg/broker` 实现外部数据源适配，外部 DTO 在进入领域前完成解析和校验。
- `api` 负责传输校验、调用应用服务和响应映射，不直接访问 GORM 或编写业务规则。
- `business`、`data`、`model` 保留财报、宏观和旧迁移兼容职责，不得形成与新技术策略内核平行的实现栈。

模块索引和允许依赖见 [领域地图](domain-map.md)。

## 3. 全局业务不变量

### 3.1 时间与数值

- 瞬时时间使用 UTC `time.Time`，MySQL 使用 `DATETIME(6)`；进入持久化边界前截断到微秒。
- 交易日期使用独立 date-only 语义，不用自由格式字符串或带时区时间戳替代。
- Price 和 Money 使用缩放 10000 的有符号整数；版本与序号使用无符号整数。

### 3.2 身份

- 证券使用包含交易所的完整身份，例如 `SSE:600000` 或 `SHFE:AU.MAIN`。
- 不透明身份字段按 UTF-8 字节限制，精确区分大小写和尾空格。
- API、领域校验和数据库列必须实施一致的长度与比较语义，不能由数据库截断或大小写不敏感排序规则修正输入。

### 3.3 行情版本

- 新计算只读取大于 0 的 `COMPLETE` 行情版本。
- 请求使用版本 0 时只允许在入口解析一次最新完成版本；任务执行和后续分页始终绑定解析后的正版本。
- 行情发布先形成不可见的新版本，全部校验与写入完成后一次切换为 `COMPLETE`；消费者不得看到部分版本。
- 周线由日线本地确定性聚合，只发布已经结束的 ISO 周；当前周进入下一 ISO 周后才成为可发布周线。

### 3.4 策略与回测时间线

- 指标预热期返回无效值，不用零值伪装有效结果。
- 信号在当前 Bar 收盘后产生，订单最早在下一根可交易 Bar 开盘成交。
- 策略不得读取未来 Bar；修复旧的未来数据问题可以改变历史信号与收益。
- 策略行为变化必须新增策略版本；撮合、成本或引擎语义变化必须提升 `EngineVersion`。

### 3.5 任务和结果

- 回测和扫描任务固定行情版本、证券集合、策略版本、参数、执行配置与引擎版本，从而能够重复执行。
- HTTP 请求结束或同步等待超时不取消已经持久化的任务；显式取消和服务停机有独立语义。
- 扫描一次最多处理 5000 个证券，必须通过 `BatchDatasets` 有界批量加载，不恢复逐证券 Repository 查询。
- 单证券失败允许扫描得到 `PARTIAL_SUCCEEDED`；成功结果与失败分类在同一不可变快照发布。
- 快照分页绑定 `SnapshotID` 和持久化序号，新快照发布不得改变已经开始的分页。

## 4. 关键端到端流程

### 4.1 行情采集与发布

1. 调度器或兼容 API 选择证券并触发应用服务。
2. Broker 在共享进程级限频器下请求外部来源，解析原始响应。
3. 应用服务验证日期、Bar、复权因子、公司行动和跨周期一致性。
4. MySQL 适配器在短事务内分配版本、写入修订并原子发布。
5. 读取方只解析完成版本。

A 股使用新浪原始日线和前复权因子，近期 20 根日线重叠增量刷新；期货 `.MAIN` 来源按配置历史起点读取完整历史，以发现早期修订。股票与期货共用同一限频器，间隔不得低于 5 秒。

### 4.2 图表与行情查询

1. API 校验证券、周期、价格视图、范围、版本和指标预算。
2. 应用服务解析一次完成版本，在完整历史上下文计算指标。
3. 返回页按时间升序，向前分页继续使用相同版本和排他游标。
4. 客户端取消陈旧请求，不能让旧响应覆盖新查询状态。

详细 HTTP 契约见 [API 文档](../../api/api.md)。

### 4.3 扫描

1. 创建请求固定策略定义、参数、时间窗、证券集合和行情版本。
2. 持久化 Worker 领取带租约的任务并定期续租。
3. 应用层批量读取全市场数据，以固定 Worker 为每只证券创建独立策略实例。
4. 结果稳定排序后，与失败分类、Run 终态和完成事件原子发布。
5. 后续读取通过 SnapshotID 保持不可变分页。

### 4.4 回测

1. 创建请求固定证券、策略、行情版本和完整执行配置。
2. Worker 加载带预热上下文的数据，账户从请求窗口开始。
3. 策略按时间线产生动作，撮合器在下一可交易 Bar 执行订单并计算费用。
4. 汇总、订单、成交、权益、Run 终态和完成事件原子发布。
5. 取消、失租或引擎失败不得发布成功结果。

## 5. 一致性与失败边界

- 外部 HTTP 不在数据库事务中执行，长计算不持有数据库事务。
- 数据库唯一约束、条件更新和稳定锁顺序负责并发仲裁，应用层预检查不能替代数据库约束。
- 可重试只适用于明确的临时、超时、死锁或连接类错误；取消、失租和确定性业务错误不重试。
- 错误沿调用链用 `%w` 保留原因，只在有处理责任的边界记录一次；API 和持久化结果不得泄露 SQL、凭据、路径、响应正文或堆栈。
- 批量任务汇总成功与失败数量，不在高频循环逐 Bar 或逐 SQL 输出 Info 日志。

## 6. 部署与迁移

- Go 1.25.7+、Node.js 24+、MySQL 5.7 或 8.0。
- 镜像不包含本地配置、凭据、转储或导出包，进程以非 root 用户运行，配置只读挂载。
- 本项目允许停机更新。数据库语义变化默认按“停服务、备份、迁移、校验、启动”执行。
- 不默认建设双写、影子表、灰度读、在线回填或长期跨版本兼容；只有明确不停机需求或数据量证明确需在线迁移时才增加复杂度。

## 7. 质量门禁

- 新业务逻辑有单元测试，总覆盖率不低于 80%。
- `internal/market`、`internal/indicator`、`internal/strategy/...`、`internal/backtest` 各自不低于 90%。
- 快速检查：`npm --prefix web run check && go test ./... && go vet ./...`。
- 完整门禁：`bash scripts/verify.sh`，包含 Race、性能、MySQL 5.7/8.0 集成和镜像检查。
- Docker 不可用时必须明确报告未通过的真实集成与镜像步骤，不能用 SQL mock 或只编译替代。
