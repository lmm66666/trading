# 扫描工作台设计

## 1. 基线与目标

源码基线为 `a71c871ccf959df4636c0f043258d2bc7bdc96c1`。当前 `ScanPanel` 用空 status/error 判断未扫描，恢复任务期间因此显示放大镜；`useRunPolling` 将所有失败重试三次；API 客户端丢失 HTTP 状态，仅保留 message。截图 NOT_FOUND 的实际请求来源尚未运行时确认。当前 SVG CSS 已为 40px，“巨大图标”仍属运行时验证项，不能声称根因已确定。

当前设计规定扫描采用左配置右结果布局、仅恢复最近任务标识。本目标明确将扫描改为顶部条件与下方结果，并增加有限表单偏好；回测保持双栏。目标批准后回填当前前端设计，草稿不覆盖它。

## 2. 页面布局（SCAN-001、005、007）

```text
策略扫描
[策略：底部倍量回撤 v1] [起始日期 → 截止日期] [开始扫描]
[交易所：全部] [策略参数 ▾] [高级设置 ▾]
说明：取窗口内最后一根可用 K 线的信号，并非区间内全部信号

任务状态：运行中 / 连接中断等                      [取消 / 重连]
扫描结果：已完成 · 策略版本 · 原始日期 · 原始范围
条件已修改，下面仍为上次扫描结果（仅有差异时显示）
证券名称 | 代码 | 信号日期 | 入选原因
已加载 N 条 [加载更多]                         [处理失败 N 只 ▾]
```

采用现有深色变量和蓝色主操作；正文 14px、辅助文字 12px、控制项高约 36px。图标 24–32px，空态为紧凑说明，无大背景插画。结果区域使用剩余空间；窄屏条件换行，表格必要时仅自身水平滚动。控件有可见标签、键盘焦点、错误说明；动态状态通过 status/alert 表达。交易所明确“全部”选项，其提交仍为现有空 exchanges 数组；高级设置保留仅活跃证券和数量上限。

日期输入继续沿用现有时区转换与区间校验，不改变截止日语义。无草稿时保持日期未选，避免引入未经确认的默认窗口；有草稿时完整恢复。日历复用现有控件，扫描可提供外部 date 输入，避免改变回测使用方式。

内置策略和已知参数用本地展示名称映射；未知项使用服务端 ID/参数名。有效参数以目录默认值合并显式输入用于展示，提交继续保留服务端默认参数语义；不在前端复制计算规则。

## 3. 数据来源与流转（SCAN-004、006）

策略目录 → 编辑草稿 → 校验并冻结本次请求 → POST scan-runs → GET 状态 → 终态 snapshot_id → 快照首屏 → 原子替换展示结果 → 固定 SnapshotKey 续页。

三个状态分别保存：

1. draft：当前编辑条件；本地保存一份，校验 JSON 结构、参数有限数值、日期和数量边界，损坏值回落安全默认值。
2. activeRun：最近创建/恢复的任务 ID 与匹配该 ID 的提交上下文。
3. displayedResult：最近已成功读取首屏的结果、对应任务及上下文、分页和滚动位置，仅在内存中保存。

localStorage 保留 `wb.scan_run_id`，新增一个带版本的扫描偏好对象，最多包含一份 draft 和一份最近提交上下文；无历史列表。先保存匹配 ID 的上下文，再切换当前 ID；启动时严格比对 ID，任何缺失/不匹配均显示“原始条件未保存”，不误绑草稿。浏览器存储失败时会话仍可工作，提示设置无法在刷新后恢复。

App 保留已访问扫描面板的 React 状态，隐藏期间停轮询、阻止续页，返回恢复；可通过 active 属性控制副作用，隐藏节点不能被键盘或辅助技术访问。刷新不恢复旧结果内存，仅查询保存的最新任务。服务端数据是任务和结果的唯一事实来源，本地提交上下文只作为来源说明，并标明它的性质；恢复时至少校验任务 ID、策略及版本一致。

继续使用既有 t_compute_runs → t_signal_snapshots → t_signal_snapshot_rows 关系和 snapshot_id/sequence 分页，不新增表、字段、索引、事务或接口。接口不提供完整原始条件、完整总数或百分比时，页面不推算伪造。

## 4. 状态与恢复（SCAN-002、003、004）

| 场景 | 行为 |
|---|---|
| 无任务 | 紧凑未扫描提示；不轮询 |
| 有 ID 尚无响应 | 恢复中，不显示未扫描 |
| 确认 GET 任务返回 404/NOT_FOUND | 立即停轮询，清除匹配的失效引用，保留草稿；解释“上次扫描记录已不可用” |
| 网络失败 | 沿用 2 秒、连续 3 次上限；保留任务与展示结果，之后手动重连 |
| 其他非重试业务错误 | 停止并给可理解提示；不按任务失效清空引用 |
| 提交新扫描 | 提交冻结的草稿；提交按钮防重入；成功后跟踪新任务，旧结果仍可见并明确标注 |
| 活动任务排队或运行 | 禁止再次创建，但允许编辑下一次条件；保留取消入口 |
| 成功/部分成功 | 用新 snapshot_id 加载候选结果；首屏成功才切换 displayedResult |
| 新快照读取失败 | 保留旧展示结果，明确新任务结果加载失败并提供重试 |
| 任务失败/取消 | 保留旧结果，明确当前任务状态，不把旧结果伪装成本轮结果 |
| 新任务零入选 | 首屏成功后替换旧结果并说明无入选证券 |

HTTP 客户端引入继承 Error 的结构化错误，保留 status 和服务端业务标识，同时维持原 message 供现有消费者使用。扫描按错误类型处理，不通过任意字符串包含关系删除任务。共享轮询增加必要 loading/retry/active 能力，默认参数保留回测既有行为；扫描启用立即处理明确任务失效的策略。

所有异步成功、失败及 finally 分支均绑定任务/请求世代；旧响应不得清空新任务、改变新任务 loading 或污染新快照。首次快照和续页都应用同一规则。手动重连只重新查询，不重新 POST；创建接口沿用现有幂等字段，不扩展后台并发能力。

## 5. 组件边界与性能

ScanPanel 管理编辑/执行/展示的协调；扫描专用条件组件管理表单；扫描偏好模块只负责有界存储与校验；ScanResults 管理固定快照读取和分页；useRunPolling 管理状态请求。避免新建通用状态框架或额外依赖。App 只承担面板存活与可见性，不承接扫描业务规则。

最多一份正在加载的新结果、一份已展示结果；分页仍每页 100、最大证券数沿用 5000。只为活动视图轮询；输入编辑不发起计算或行情读取。数字和代码使用等宽数字；不新增在线字体、追踪或外部服务。

## 6. 兼容、取舍与回滚

沿用旧任务 ID，无业务数据迁移。新增偏好可删除；旧版本忽略新 key 即可回退。保留原 UI 的方案变动更小，但不利于频繁调参；完整历史比较中心涉及新的任务查询和持久化，留待独立需求。

旧任务缺失条件直接说明，不追加后端输入回显 API；这避免本次扩大持久化契约。跨刷新保留全部已加载结果不在范围内。已有预热/新鲜度语义待决项不在本次处理。

## 7. 测试及当前文档

按 SCAN-001 至 008 写先失败的回归测试：恢复中无空态；明确 404 只请求一次并清理正确 ID；网络三次失败后重连；隐藏停止/返回恢复；旧响应各分支隔离；草稿不改结果标签；新结果失败保留旧结果、零行成功替换；分页数字正确；旧存储兼容、损坏偏好、存储拒绝；日期和键盘操作；回测回归。

生产实现完成后执行 `bash scripts/verify.sh`，覆盖率遵守工程标准；复杂变更启动独立子 Agent 评审。MySQL 门禁不适用（无持久化/SQL 变化），镜像门禁不适用（无打包/构建依赖/部署变化）；如实施范围触发则补跑。浏览器视觉验证须先按用户规则取得许可，未做时如实记录，不能用 DOM 测试宣称已验证像素布局。

回填 docs/design/web.md 的组件、布局、偏好及状态契约；无需新增 ADR，不修改扫描算法和 HTTP 服务端契约。
