# NAS 数据更新与电脑工作台拆分需求

## 问题与使用场景

当前一个 Go 进程同时运行行情采集、股票/期货调度、查询 API、前端页面以及扫描/回测 Worker。用户希望 NAS 持续更新数据，电脑上的工作台按需启动；电脑关机不影响更新。

现状基线为 `1975cbd06cb90b1f9e3fc4b363189f89668fd09a`。本次只调整部署与运行边界，不调整策略、指标、行情口径或界面布局。

## 环境、频率与数据量

- 用户于 2026-09-21 确认 NAS 支持 Docker，CPU 为 AMD；镜像按工程标准构建为 linux/amd64。
- 电脑有保存 mock 数据的 MySQL，NAS 有保存全量股票数据的 MySQL；两库独立，不做自动同步或数据覆盖。
- 当前仅局域网访问，未来希望外网访问。本次交付局域网部署；外网接入不在本次实施范围。
- 用户确认更新频率、采集范围保持现状：股票调度启动即执行，后续按现有 24 小时 ticker；沪深北活跃证券范围上限 5000；股票重抓最近 20 根日线，期货沿用固定八个主力连续品种及全历史刷新。期货启用开关、刷新间隔和共享限频沿用现有配置。
- 上述 5000 是当前代码上限，不是已测得的 NAS 实际证券数。数据库行数和体积未测量，本次不引入依赖容量估算的数据迁移或同步。
- 单用户、每个目标库一个更新实例及一个工作台实例；不增加多副本调度能力。

## 需求与验收

| ID | 需求 | 可观察验收标准 |
|---|---|---|
| REQ-SPLIT-001 | 只保留 updater、workbench 两种启动方式 | 未指定/非法角色启动失败；不存在 all 模式；本地可启动两个独立进程 |
| REQ-SPLIT-002 | NAS 是行情唯一发布者 | updater 装配采集和调度；workbench 不创建 Broker/调度器，不直接刷新或发布行情 |
| REQ-SPLIT-003 | 保持采集行为 | 现有股票/期货范围、增量窗口、共享限频、周期、版本原子发布测试继续通过 |
| REQ-SPLIT-004 | 电脑提供完整工作台 | 图表、指标、自选、看板、扫描与回测继续可用；查询绑定 COMPLETE 版本，分页与任务契约不变 |
| REQ-SPLIT-005 | 页面刷新在 NAS 执行 | 原刷新路径和请求/成功结构保持；单证券同步、全市场异步；重复刷新仍返回 429 |
| REQ-SPLIT-006 | 两服务独立生命周期 | 关闭工作台不停止更新；更新服务短暂不可达时，数据库可达则查询和计算仍可用；刷新明确报不可达/超时 |
| REQ-SPLIT-007 | 数据库按用途连接 | 正常使用两服务连接 NAS 同一业务库；本地调试显式连接本地库；不自动降级到 mock 库 |
| REQ-SPLIT-008 | 明确启动迁移归属 | updater 在调度启动前完成现有 schema 初始化；workbench 只连接数据库，不执行 DDL；不新增/删除业务表或索引 |
| REQ-SPLIT-009 | 可部署、基础访问控制 | 提供两个镜像目标、NAS Compose 示例与两份无凭据配置示例；更新接口校验服务 Token；工作台默认仅监听本机 |
| REQ-SPLIT-010 | 安全切换和验证 | 停旧进程后启动 updater 再启动 workbench；真实 MySQL 隔离库、双镜像、本地门禁和独立代码评审通过后才能合并 |

## 范围与非目标

包含组合根拆分、刷新 HTTP 边界、配置与启动入口、数据库初始化归属、镜像及部署手册、必要测试和当前设计回填。

不包含公网发布、VPN 配置、多用户、离线浏览、行情复制、独立行情数据库、消息队列、服务注册中心、跨进程刷新租约、刷新任务持久化、新调度策略，以及将扫描/回测迁至 NAS。

## 兼容性

用户已明确同意不保留原单体运行方式。现有启动命令需增加服务角色，配置和镜像部署方式按目标设计升级。现有业务 API 保留，仅刷新新增远端故障状态；不增加旧单体兼容层。

NAS 全量库保持原有内容；本次不执行旧行情导入、批量重建或 mock 数据覆盖。若部署前发现 NAS schema 不符合现有内核要求，按已有迁移流程单独处理，不把未知迁移纳入拆分。

## 批准范围与证据

对话已确认部署目标、现有环境、更新频率与采集范围保持现状、取消单体运行方式。这些决定作为需求输入。

本文件与 [目标设计](design.md) 是待审阅的具体方案；用户尚未批准共享库、内部 HTTP、迁移归属及新配置的完整内容版本，因此审批字段保持空值。后续批准需绑定两文件的内容版本。验收记录见 [验证](verification.md)。
