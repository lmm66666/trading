# 扫描工作台重设计 requirements

## Problem and user scenarios

用户在工作台「扫描」页运行策略信号扫描并复查入选名单。当前页面（`web/src/features/scan/`）存在五类可观察的可用性问题：

1. 任务状态条把 64 位 run_id 哈希整串平铺在结果区顶部，用户关心的策略、时间范围、完成时间反而不可见。
2. 入选 0 只时结果区只剩空表头，无空态说明；状态条与结果表是两张漂浮的薄卡片，右栏大部分为空白。
3. 配置栏区块标题「策略」与表单字段 label「策略」重复出现两行。
4. 结果表格只有「证券 ID + 信号时间」两列；接口已返回的 `reason` 未展示，证券名称缺失，用户无法直接辨认入选证券。
5. 证券名称在前端无可靠数据来源，需要服务端在既有契约上补充。

已确认的设计前提：

- 策略参数继续以英文参数名直接作为表单 label（用户 2026-09-21 裁决，不需要中文 label）。
- 一次扫描每只股票最多一个信号行：`ReplayLatest` 只保留窗口最后一根 bar 的决策，`SignalSnapshot.Validate` 强制 instrument 不重复。同一快照内各行信号时间通常相同（窗口最后一根 bar 收盘时间），停牌股可能更早，故信号时间列保留。

## Environment, frequency, and data volume

- 桌面 Web 工作台（本机按需运行），后续拆分为电脑上的前后端服务，数据与本变更无关。
- 人工触发扫描，频率低；单次扫描证券上限 5000，结果分页读取（前端每页 100 行）。
- 证券名称来自 `t_instruments`，单页结果行最多 100 行，名称解析为等量级小批量查询。

## Requirements

- `REQ-SCAN-UI-001`：任务状态条以人类可读信息为主：状态徽标、策略 ID 与版本；run_id、数据版本、尝试次数、取消标记收进可展开的「任务详情」，默认不展示完整 run_id。状态条不显示扫描时间范围与完成时间：`RunStatus` 契约不含这两项（用户 2026-09-21 二次裁决，不为此扩展任务契约）。
- `REQ-SCAN-UI-002`：结果区合并为单张结果卡：卡头为状态条，卡体为入选计数（含部分成功时的失败徽标）与结果表格；表格列为代码、名称、信号时间、信号原因；点击证券仍跳转图表视图。
- `REQ-SCAN-UI-003`：入选 0 只时结果卡显示明确空态（无入选证券及调整建议）；结果加载中显示骨架行而非纯文本。
- `REQ-SCAN-UI-004`：`GET /api/v1/signal-snapshots/latest` 的结果行与失败行新增 `name` 字段（证券名称）；名称缺失时字段省略，前端回退显示证券代码。
- `REQ-SCAN-UI-005`：配置栏删除重复的「策略」字段 label；策略元信息（主周期、预热根数、默认持有根数）以 chip 形式展示。
- `REQ-SCAN-UI-006`：扫描语义、任务生命周期、快照分页契约、请求字段与校验规则均不变；既有客户端忽略新增字段后行为不变。

## Acceptance criteria

- 扫描页状态条默认不显示完整 run_id；展开「任务详情」可见 run_id、数据版本、尝试次数。
- 发起扫描并完成（含部分成功）后，结果卡表格展示代码、名称、信号时间、信号原因四列；名称为 `t_instruments` 中该证券当前名称。
- 入选 0 只的任务展示空态文案而非空表头；加载期间展示骨架行。
- `/api/v1/signal-snapshots/latest` 响应行含 `name`；契约文档与契约测试同步更新。
- 配置栏不再出现重复「策略」标签；策略参数仍以英文参数名作为表单 label。
- 回测页共用组件（RunMonitor、StrategyForm）随本次改进同步生效，回测页既有行为回归通过。

## Scope and non-goals

范围：扫描页视图重组与文案层级；`/api/v1/signal-snapshots/latest` 的响应字段新增；快照读取路径关联证券名称。

非目标：

- 不改变扫描计算语义、窗口/预热规则、快照不可变性、幂等与取消行为。
- 不改变请求字段、校验规则、分页游标语义与状态机。
- 不改 `/api/v1/strategies` 契约与策略内核参数元数据（参数保持英文 label）。
- 不重做回测页布局；不引入结果排序、筛选、导出、迷你走势图等新能力。
- 不为历史快照回填名称（名称按读取时 `t_instruments` 当前值解析，属显示属性而非快照内容）。

## Compatibility and open questions

- 兼容性：端点为纯新增可选字段，不改变既有字段语义；旧前端忽略新字段后行为不变。无需迁移。
- 名称解析时点：结果行名称为读取时点的证券当前名称，不随快照固化；证券更名后旧快照按新名称显示。此语义需在契约中写明。
- 无未决开放问题。
