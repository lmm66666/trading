# 回测工作台目标设计

## 1. 布局与输入（BT-001）

沿用工作台暗色/蓝色、间距、焦点语义；使用回测独立样式范围。顶部常用条件，下方横向报告；窄屏条件逐行，表格仅局部横向滚动。证券沿用搜索服务，名称来自搜索/当前证券；恢复草稿优先于当前图表默认证券，不暗中覆盖用户选择。日期不强加窗口，优先恢复设置。

策略目录来自现有接口；首个策略作为初次默认，目录失败可重试。有效参数在提交时合并目录默认及显式输入并冻结；持有期空/0仍采用目录默认。百分比接受0.01%步长（资金比例0.01–100%，费用0–100%），提交转换整数bps；金额和范围沿用原契约。所有输入提交前校验，错误靠近字段。费用折叠摘要可见。

## 2. 数据来源与任务生命周期（BT-002至BT-004）

沿用 POST backtest-runs → 任务ID → 状态轮询 → 成功summary → 按run_id读取equity/orders/trades。所有业务数据由既有接口提供；无库表、索引、事务变动。2秒轮询、三次连续临时错误停止；复用已具备结构化错误分类的polling hook，404 NOT_FOUND清除对应引用；网络错误不清理。

状态分为draft、submitted、report：草稿可编辑，submitted冻结任务ID/输入/有效参数及实际持有期；SUCCEEDED+summary一次替换report，报告内资源以run_id作为组件key，显示新任务加载态，绝不挂旧曲线。运行/失败时旧report保留并说明其身份。仅保留当前会话上一次展示报告，不增加历史比较仓库。

App首次访问后保留BacktestPanel，隐藏时暂停轮询及资源请求/后续分页，关闭弹层；返回可恢复查询及现有内存分页。localStorage wb.backtest_preferences version=1只保存一份草稿和一份submitted，限制长度、结构校验、失败提示；刷新重新读服务端，不恢复整份report数据。只有任务ID、策略、版本与服务端吻合才能关联本机提交记录；缺少上下文显示原始条件未保存。新方案兼容已有任务ID，不对旧任务猜测参数。

## 3. 报告与分页（BT-005、BT-006）

报告标题显示本机提交的证券/日期以及服务端策略版本，运行条件详情展示完整冻结输入并注明本机来源。数据版本/引擎版本来自状态响应。主指标四项，辅助胜率、盈利因子、平均持有和期末持仓；null用—及解释，零平仓不误写成无成交。

权益图元单位；十字线读equity/cash/position_value原字段。每页1000、最多10页沿用上限；达到上限且还有游标必须显示未完整提示，不冒充全部。曲线加载失败可重试，切run无旧状态/数据残留。

成交默认标签，订单按需读取；每页100，续页串行并隔离旧请求所有分支。切标签保留已读分页，错误不清除已有行；首屏错误可重试，空表明确提示。ID/费用可在每行详情中查看，成交价格不按金额截为两位。

## 4. 工程边界及验证（BT-007）

复用RangePicker、useRunPolling、API client、策略目录和搜索，不引入任务框架或新依赖。长期规则回填 docs/design/web.md。测试先证明恢复/失效、转换/验证、冻结上下文、报告保留/切换、分页竞态及权益截断，再实现。全量 scripts/verify.sh；本次无持久化/SQL或构建部署变化，MySQL和镜像门禁不适用。按仓库规则独立子agent复核架构、遗留清理、简化及BUG。回滚仅回退前端提交，新增浏览器偏好可丢弃。
