# 回测工作台需求

## 场景及批准依据

用户在完成扫描页改造后要求“回测页面，一起改了吧。也先设计一下”，在收到顶部调参、下方报告及五项交互方案后回复“嗯 没问题”。2026-09-21 的该回复批准本次范围；本文是对该会话方案的落实记录，不扩大业务能力。使用方式保守按个人手动反复调整条件设计；不假定具体调用频率，不增加自动回测、批量标的或跨任务比较。

## 范围及验收

- BT-001 顶部证券名称/代码、策略版本、日期、运行入口；直接日期输入和日历；初始资金、资金比例、持有期常驻，参数和成交费用折叠。百分比精确映射原有整数 bps，金额映射原缩放整数；原默认值及引擎规则不变。
- BT-002 区分草稿、当前任务、报告；编辑及新任务运行期间保留上份报告，成功后统一切换报告身份，曲线/明细只能显示同一任务数据。失败保留旧报告，局部资源可重试。
- BT-003 页面切换保留草稿、结果、分页、滚动；浏览器刷新恢复有限设置及最近提交条件，不保存结果数据。原任务 ID 仍可读取，缺少原始条件明确说明。
- BT-004 区分未运行、恢复中、排队、运行、失败/取消、任务不存在、连接中断；确定不存在时停止重试并清理对应引用，临时失败支持重新连接。提交及活动任务期间阻止重复创建，允许编辑下一次条件。
- BT-005 四个主指标（总收益率、最大回撤、年化收益率、平仓笔数），辅助指标解释 null 与期末持仓。权益曲线单位元，悬停显示日期、权益、现金、持仓市值；分页上限不能静默截断。
- BT-006 成交/订单标签页，时间、方向、价格、数量、金额优先，技术 ID/费用放详情；价格最多四位小数，金额两位；分页显示已加载，零记录及首屏/续页错误可识别并重试。异步成功/错误/收尾都隔离旧任务。
- BT-007 维持单标的接口、撮合、费用、引擎、数据库和部署不变；全量本地门禁、覆盖率及独立 review 通过后合并。

## 边界

不新增任务历史、基准、夏普、逐笔盈亏配对或自动取消。`trades` 仍是成交记录。现存 wb.backtest_run_id 原样使用，新增设置是可丢弃浏览器偏好，不迁移后端数据。桌面与窄屏适配，图标明确限宽高。

见 [设计](design.md) 和 [验证](verification.md)。
