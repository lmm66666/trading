# 第一批：让扫描和 B1 设计可以分层阅读

用户已在本任务认可 B1 样稿，并对紧接其前的文档规划回复“嗯 可以”。上述批准引用指向该次对话规划，不表示用户逐字批准了本次生成的文件，也不批准新业务规则。文件最终修订由 Git 提交追踪。

原样稿把业务规则、扫描流程、接口表关系和公共策略契约放在同一文件，用户难以按问题定位。第一批拆为扫描流程、B1 规则和原有技术契约，通过功能导航连接；每条规则有明确阅读位置，避免全文复制。

| 需求 | 验收 |
|---|---|
| READ-001 | 导航按业务问题组织，保留实现地图，并明确第一批与未完成范围 |
| READ-002 | 扫描文档说明窗口、固定输入、失败、数据流、接口及表关系；B1 文档说明阈值、状态、实例和修改影响 |
| READ-003 | 原策略模块移除混合样稿，保留全部公共技术契约；文档相互链接且路径和锚点有效 |
| READ-004 | 新说明明确代码基线、证据和未决行为，不冒充批准契约；现有源码所有权和技术契约检查保持有效 |
| READ-005 | 本地门禁与独立评审通过，记录实际检查及未执行范围，不改生产代码 |

使用条件：单仓库文档，在理解、设计和评审时阅读；无需访问量、缓存或额外平台设计。保留当前业务和工程语义，其他三个批次、本机 skill、其他任务的财报宏观清理均不属于本次范围。

目标设计见 [design](design.md)，实际证据见 [verification](verification.md)。本次发现的预热契约措辞与实现差异只记录，不静默裁决或修复。
