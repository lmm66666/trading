# 扫描工作台需求

## 场景与范围

用户反馈进入扫描页先出现巨大放大镜，随后显示“轮询异常 NOT_FOUND”，并要求改进 UI。2026-09-21 用户确认主要使用方式为“经常调整策略和日期，反复扫描比较”，并回复“嗯 继续”同意继续细化此前提出的顶部条件区与下方结果区方案。

本次是前端交互和状态生命周期的复杂变更。既有个人工作台部署背景沿用；手动扫描，输入修改不调用计算接口；每次最多 5000 个证券、结果每页 100 条、活动任务每 2 秒轮询沿用现状。这是容量边界，不是假定实际频率或性能测量。无需新增缓存服务、并发任务队列或数据库表。

## 需求与验收

- `SCAN-001` 顶部常用条件与下方结果布局：策略、日期、交易所、开始扫描可直接操作；策略参数和高级范围设置按需展开。适配窄屏，不产生页面级横向溢出。
- `SCAN-002` 首次加载明确区分未扫描、恢复中、排队、运行、成功、部分成功、失败、取消和连接异常。有任务 ID 时不得闪现“尚未扫描”。空态图标具有元素尺寸和 CSS 双重约束。
- `SCAN-003` 状态查询明确返回任务不存在时停止重试，清除该失效任务引用并解释原因；网络失败不清除任务或已有结果，达到重试上限后支持手动重连。所有清理只作用于产生该响应的任务。
- `SCAN-004` 保留表单草稿与最近提交条件，区分草稿、正在执行的任务、已展示结果的来源。编辑条件或提交新任务不清空旧结果；新结果首屏读取成功后才替换，零入选也属于有效新结果。
- `SCAN-005` 结果展示策略版本及可验证的提交条件、名称、代码、信号日期和原因；分页未结束时显示“已加载 N 条”，不能当成总数。部分失败单列，分页失败保留已加载行。
- `SCAN-006` 从结果进入图表再返回扫描，恢复当前会话内条件、结果、分页和滚动位置；离开扫描停止任务轮询，返回再恢复。浏览器刷新只恢复有限元数据，重新读取服务端快照，不持久化整张结果表。
- `SCAN-007` 日期支持直接输入、快捷范围及日历；明确扫描取窗口内最后一根可用主周期 K 线信号，不是区间内全部历史信号。策略名中文展示、版本弱化；未知策略保留原 ID。
- `SCAN-008` 回归覆盖失效引用、重连、连续提交、旧响应、表单/结果隔离、分页与返回恢复；全量门禁和独立代码评审通过后才能合并。

## 边界及兼容

保留扫描请求、策略计算、快照分页、数据库和上限规则。不新增历史任务列表、跨任务差异计算、自动扫描、数据新鲜度判定、涨跌统计或虚构进度百分比。

保留现有 `wb.scan_run_id` 读取；旧任务缺少完整条件时明确显示“原始条件未保存”，不从当前表单推断。新增草稿仅为可丢弃的浏览器偏好；不迁移业务数据，不增加历史格式适配栈。已有回测视图布局和轮询行为不在本次改造范围。
