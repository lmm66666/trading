## 1. 背景与问题

开发机和部署环境使用不同 CPU 架构：本地 Docker 宿主为 `linux/arm64`，部署环境为 `linux/amd64`。现有集成测试依次启动 `mysql:5.7` 和 `mysql:8.0`；MySQL 5.7 官方镜像在本地缺少原生 ARM64 支持，会触发跨架构模拟，增加耗时和失败面。

部署数据库的只读协议握手显示版本为 MySQL 8.4.5。项目继续承诺 MySQL 5.7/8.0 双版本会让设计、测试矩阵和实际部署基线长期分离。

## 2. 目标

1. 将项目唯一受支持的数据库基线统一为 MySQL 8.4 LTS。
2. 本地集成测试使用官方 `mysql:8.4` 多架构镜像，由 Docker 在 ARM64 宿主选择原生 manifest，不进行 amd64 模拟。
3. 部署应用镜像明确构建为 `linux/amd64`，与生产宿主一致。
4. 提供只读部署数据库兼容性检查，验证版本和编译架构，不迁移、不写表、不读取业务数据。
5. 删除文档、测试和代码注释中的 MySQL 5.7/8.0 双版本承诺。

## 3. 非目标

- 不修改业务表结构、持久化语义或已有数据。
- 不因升级基线而改用 `SKIP LOCKED`、窗口函数等 MySQL 8 专属实现。
- 不在部署数据库运行 AutoMigrate、集成测试或任何写入语句。
- 不把部署密码、完整 DSN、内网地址或端口写入 Git 跟踪文件。
- 不建设多架构发布流水线或镜像仓库推送流程。

## 4. 当前行为

- 11 个集成测试文件的 17 个位置分别硬编码 `[]string{"mysql:5.7", "mysql:8.0"}`。
- `scripts/verify.sh` 宣称并执行 MySQL 5.7/8.0 双版本门禁，最终应用镜像只按当前 Docker 宿主构建。
- `AGENTS.md`、系统设计、运行手册、Roadmap 和 MySQL 模块设计继续承诺两个旧版本。
- 本地宿主和 Docker daemon 均为 ARM64；部署数据库协议版本为 MySQL 8.4.5。

## 5. 目标行为

### 5.1 数据库版本

`mysql:8.4` 是集成测试唯一镜像，由测试夹具集中定义。所有测试仍使用隔离数据库容器，并保留真实 DDL、事务、锁、索引和身份排序验证。

最低运行版本为 MySQL 8.4。现有 SQL 可以继续采用兼容写法；删除 MySQL 5.7 支持不授权顺带重构队列、迁移或锁实现。

### 5.2 架构矩阵

| 环境 | CPU 架构 | 验证方式 |
|---|---|---|
| 本地开发与集成测试 | `linux/arm64` | Docker 自动选择 `mysql:8.4` 的 ARM64 manifest |
| 部署数据库 | `linux/amd64` | 只读查询版本和 `@@version_compile_machine` |
| 部署应用镜像 | `linux/amd64` | Buildx 显式按 `linux/amd64` 构建 |

禁止给本地 MySQL 容器硬编码 `platform: linux/amd64`。同一 `mysql:8.4` 标签在不同宿主上解析对应原生镜像。

### 5.3 部署检查

部署检查通过单独的 Go integration test 执行，只允许以下只读操作：建立连接、`PingContext`、查询 `VERSION()` 与 `@@version_compile_machine`。DSN 仅从进程环境读取；错误消息不得打印 DSN 或密码。

该检查不进入无凭据的本地 `scripts/verify.sh`，但在本次需求验收时必须对指定部署数据库运行一次并记录脱敏结果。

## 7. 方案比较与选择

选择 MySQL 8.4 LTS，而不是继续双版本或固定 8.0：

- 8.4 与当前部署数据库 8.4.5 一致，减少环境漂移。
- 官方标签采用多架构 manifest，可让 ARM64 本地和 AMD64 部署各自使用原生镜像。
- 单版本真实集成测试降低重复容器启动成本，同时仍覆盖项目唯一受支持的数据库。

未选择 `mysql:8` 浮动标签，因为其目标版本会随上游变化；未选择本地模拟 amd64，因为它不能替代部署环境原生验证且显著增加耗时。

## 8. 接口、数据与兼容性

HTTP API、领域模型和表结构不变。部署数据库已经是 MySQL 8.4.5，因此无需业务数据迁移。

本变更明确终止 MySQL 5.7 和 8.0 的支持承诺；仍运行这些版本的环境必须先自行升级到 8.4，项目不提供双版本兼容期。

## 9. 风险与失败处理

- Docker Registry 拉取超时必须作为环境失败报告并重试，不能回退到本地 amd64 旧镜像。
- `mysql:8.4` 若无法解析本机原生 manifest，集成门禁失败，禁止强制指定 amd64 绕过。
- 远端检查缺少 DSN、连接失败、版本不是 8.4 或架构不是 x86_64 时明确失败，但只输出脱敏分类。
- 部署检查绝不调用 `Migrate`、AutoMigrate 或业务 Repository，避免对生产数据产生副作用。

## 10. 测试与验收标准

1. 仓库正式文件中不存在 MySQL 5.7/8.0 双版本支持声明或 `mysql:5.7` 测试镜像。
2. 文档契约测试、快速检查和 `bash scripts/verify.sh` 全部通过。
3. 本地 MySQL 集成测试只启动 `mysql:8.4`，容器架构为 ARM64。
4. 部署兼容检查只读通过，报告 MySQL 8.4.x 和 x86_64，不输出连接凭据。
5. 最终应用镜像以 `linux/amd64` 成功构建。
6. 总覆盖率和核心领域覆盖率继续满足 `AGENTS.md` 门禁。
