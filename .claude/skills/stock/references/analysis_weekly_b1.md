# 周线 B1 买点分析流程

> 本文档指导如何执行"周线 B1 买点"策略扫描与个股分析。执行前请先阅读 `api_reference.md` 了解 API 速查表。
>
> 周线 B1 策略与底部倍量回调是完全独立的分析模式，核心逻辑基于**周线级别 KDJ 超卖 + 均线多头排列**，不关注日线放量/缩量。

## 核心逻辑

该策略基于**周线级别趋势确认 + 超卖介入**的思路，分四条件确认：

1. **周线 KDJ 超卖**：KDJ 的 J 值 < 10，表明周线级别进入严重超卖区域，具备反弹基础
2. **周线均线多头排列**：MA20 在 MA60 之上，确认中长期趋势向上
3. **周线支撑有效**：收盘价站稳周 60 日均线，说明中期支撑未被破坏
4. **跨周期确认**：日线 MA20 形成有效支撑，短期趋势与中期趋势共振

## 形态特征

### A. 周线 KDJ 超卖信号
- KDJ 的 K、D、J 三线均处于低位区域
- J 值 < 10（严重超卖）
- 此前 KDJ 从高位回落，经过充分的调整周期

### B. 周线均线多头排列
- MA20 > MA60，且 MA20 斜率向上
- 股价主要运行在 MA20 上方或附近
- 整理期间不有效跌破 MA60

### C. 周线支撑确认
- 收盘价在周 MA60 之上
- 回踩 MA60 后能迅速收回
- 周线级别无明显放量阴线跌破支撑

### D. 跨周期共振（日线验证）
- 日线 MA20 走平或向上
- 日线收盘价在 MA20 之上
- 日线级别无系统性破位风险

## 执行步骤

### 阶段 1：获取带评分的信号列表

调用 `/api/stocks/signal/scored` 获取周线 B1 买点信号股票列表（含短线/长线评分），**将结果保存到文件**。

```bash
curl --max-time 120 "http://192.168.31.85:38687/api/stocks/signal/scored?strategy=weekly_b1_buy"
```

保存到 `.tmp/weekly-b1-scored-{日期}.json`。

> 接口返回的 `signals` 数组已按短线评分降序排列，每只股票包含 `short_detail` 和 `long_detail` 评分明细。建议超时 **120s**。

### 阶段 2：取前 10 名进行基本面深度分析（并行 Agent）

从评分结果中取**短线评分最高的前 10 只**股票，**启动并行 Agent**，每个 Agent 负责一只股票：

1. **基本面深度分析**：通过 WebSearch / WebFetch 搜索标的所属行业的发展情况，重点关注：
   - **所属行业**：标的所处行业分类
   - **行业增速**：行业近 1-3 年复合增速
   - **景气周期**：当前处于景气上行、高位、下行哪个阶段
   - **政策导向**：是否属于国家战略支持产业

   > 检索关键词示例：`{行业名称} 2026 发展前景 增速 龙头`

2. 将分析结果保存到 `.tmp/{code}-weekly-analysis.json`，格式：

```json
{
  "code": "000001",
  "short_score": 75,
  "long_score": 68,
  "industry": "银行",
  "industry_growth": "3-5%",
  "industry_cycle": "景气下行",
  "policy_support": "中性",
  "short_reason": "周线KDJ J值8.5严重超卖，MA20>MA60多头排列，日线MA20有效支撑",
  "long_reason": "净利润+12%，ROE 11%，但行业增速放缓"
}
```

### 阶段 3：汇总生成报告

1. 读取评分列表和 `.tmp/` 下所有 `*-weekly-analysis.json` 文件
2. 按短线评分降序排列
3. 按下方模板生成标准化 Markdown 报告
4. 输出到 `./docs/analysis/weekly-b1/{日期}-周线B1分析.md`
5. 清理 `.tmp/` 临时文件（可选）

## 评分标准

评分体系分为**短线评分**（周线趋势质量）和**长线评分**（财报基本面）两套独立体系，各满分 100 分。

### 一、短线评分（周线趋势质量，满分 100）

聚焦"周线 KDJ 超卖 + 均线多头排列 + 支撑确认"的质量。

#### 维度 A：KDJ 超卖程度（40 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| J 值位置 | 20 | J < 0 得 20；0-10 得 15；10-20 得 10；>20 得 0 |
| K、D 同步低位 | 10 | K < 20 且 D < 20 得 10；任一 >20 得 5；均 >30 得 0 |
| 超卖持续时间 | 10 | 超卖持续 ≥3 周得 10；1-2 周得 5；刚进入得 0 |

#### 维度 B：均线多头排列（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| MA20 > MA60 | 10 | MA20 在 MA60 之上且斜率向上得 10；在之上但走平得 5；下穿得 0 |
| 股价与 MA20 关系 | 10 | 收盘价 > MA20 得 10；回踩 MA20 得 5；跌破得 0 |
| 股价与 MA60 关系 | 10 | 收盘价 > MA60 得 10；回踩 MA60 得 5；跌破得 0 |

#### 维度 C：跨周期确认（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 日线 MA20 支撑 | 15 | 日线收盘价 > 日MA20 得 15；回踩不破得 8；跌破得 0 |
| 调整幅度 | 10 | 回调 ≤15% 得 10；15-25% 得 5；>25% 得 0 |
| 调整周期 | 5 | 调整 ≤8 周得 5；8-16 周得 3；>16 周得 0 |

### 二、长线评分（财报基本面，满分 100）

与底部倍量模式共用同一套长线评分体系，完全基于本地财报 API 数据评估。

#### 维度 A：盈利增长（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 净利润同比 | 20 | ≥30% 得 20；10-30% 得 15；0-10% 得 8；下滑扣分（-30% 以下记 0） |
| 营收同比 | 10 | ≥20% 得 10；5-20% 得 7；0-5% 得 4；下滑（<0）记 0 |

#### 维度 B：盈利质量（25 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 经营现金流 | 15 | 连续 4 期为正得 15；偶尔为正得 8；连续为负得 0 |
| 毛利率趋势 | 5 | 稳健或上升得 5；微降得 3；显著下滑得 0 |
| ROE 水平 | 5 | ≥15% 得 5；5-15% 得 3；<5% 得 0 |

#### 维度 C：财务安全（25 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 资产负债率 | 10 | ≤50% 得 10；50-70% 得 5；>70% 得 0 |
| 流动比率 | 8 | ≥2.0 得 8；1.0-2.0 得 5；<1.0 得 0 |
| 速动比率 | 7 | ≥1.0 得 7；0.5-1.0 得 4；<0.5 得 0 |

#### 维度 D：运营效率（20 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 总资产周转率趋势 | 8 | 稳健或上升得 8；微降得 5；显著下滑得 0 |
| EPS 增长趋势 | 7 | 连续增长得 7；持平得 4；连续下滑得 0 |
| 扣非净利润占比 | 5 | 扣非/归母 ≥90% 得 5；70-90% 得 3；<70% 得 0 |

### 评级映射

| 分数段 | 评级 | 含义 |
|--------|------|------|
| 90-100 | S | 极佳 |
| 80-89 | A | 优秀 |
| 70-79 | B | 合格 |
| 60-69 | C | 勉强合格 |
| <60 | D | 不达标 |

## 数据持久化规范

| 阶段 | 文件路径 | 内容 | 责任人 |
|------|----------|------|--------|
| 评分结果 | `.tmp/weekly-b1-scored-{日期}.json` | API 返回的带评分信号列表 | 主会话 |
| 深度分析 | `.tmp/{code}-weekly-analysis.json` | 前 10 名的行业分析摘要 | 分析 Agent |

> `.tmp/` 为临时目录，分析完成后由主会话统一清理。

## 注意事项

1. **评分由 API 计算**：短线/长线评分由 `/api/stocks/signal/scored` 接口的服务端算法计算，Agent 禁止手动心算量化指标

2. **前 10 名深度分析**：只对短线评分最高的 10 只做行业搜索分析，避免无差别搜索拖慢整体效率

3. **超时设置**：`/api/stocks/signal/scored` 扫描+评分耗时较长，建议超时 **120s**

4. **增量分析**：如果 `./docs/analysis/weekly-b1/` 下已有同日期报告，询问用户是否覆盖
