# 周线 B1 买点分析流程

> 本文档指导如何执行"周线 B1 买点"策略扫描与个股分析。执行前请先阅读 `api_reference.md` 了解 API 速查表。
>
> 周线 B1 策略与底部倍量回调是完全独立的分析模式，核心逻辑基于**周线级别 KDJ 超卖 + 均线多头排列**，不关注日线放量/缩量。

## 核心逻辑

该策略基于**周线级别趋势确认 + 超卖介入**的思路，分四条件确认：

1. **周线 KDJ 超卖**：KDJ 的 J 值 < 10，表明周线级别进入严重超卖区域，具备反弹基础
2. **周线均线多头排列**：MA20 在 MA60 之上，确认中长期趋势向上
3. **周线支撑有效**：收盘价站稳周 60 日均线，说明中期支撑未被破坏
4. **跨周期确认**：日线 MA20 形成有效支撑，短期趋势与中期趋势共振

## 形态特征

### A. 周线 KDJ 超卖信号
- KDJ 的 K、D、J 三线均处于低位区域
- J 值 < 10（严重超卖）
- 此前 KDJ 从高位回落，经过充分的调整周期

### B. 周线均线多头排列
- MA20 > MA60，且 MA20 斜率向上
- 股价主要运行在 MA20 上方或附近
- 整理期间不有效跌破 MA60

### C. 周线支撑确认
- 收盘价在周 MA60 之上
- 回踩 MA60 后能迅速收回
- 周线级别无明显放量阴线跌破支撑

### D. 跨周期共振（日线验证）
- 日线 MA20 走平或向上
- 日线收盘价在 MA20 之上
- 日线级别无系统性破位风险

## 执行步骤

### 阶段 1：获取并持久化信号列表

调用 `/api/stocks/signal` 获取周线 B1 买点信号股票列表，**将结果保存到文件**。

```bash
curl "http://192.168.31.85:38687/api/stocks/signal?strategy=weekly_b1_buy"
```

保存到 `.tmp/weekly-b1-signals-{日期}.json`：

```json
{
  "date": "2026-05-25",
  "strategy": "weekly_b1_buy",
  "codes": ["000001", "600000", ...],
  "total": 15
}
```

> 接口完整文档见 `api_reference.md`。扫描耗时较长，建议超时 **60s**。

### 阶段 2：批量获取股票数据（并行 Agent）

**启动多个并行 Agent**，每个 Agent 负责一批股票（建议每批 **5-10 只**），任务如下：

1. 读取 `.tmp/weekly-b1-signals-{日期}.json`，获取分配到的股票代码
2. 对每只股票调用 API 获取：
   - **周线 K 线数据**：`/api/stocks/price?code={code}&cycle=weekly&pagesize=20`
   - **日线 K 线数据**：`/api/stocks/price?code={code}&cycle=daily&pagesize=60`（用于跨周期 MA20 验证）
   - **财报数据**：`/api/stocks/financial-report?code={code}&pagesize=20`
3. 将原始数据保存到 `.tmp/{code}-weekly-data.json`，格式：

```json
{
  "code": "000001",
  "name": "平安银行",
  "weekly": { "data": [...] },
  "daily": { "data": [...] },
  "financial": { "data": [...] }
}
```

> 此阶段核心目标：**将原始数据持久化到文件**，避免在主会话上下文中堆积大量 JSON。

### 阶段 3：个股量价与基本面分析（并行 Agent）

**启动多个并行 Agent**，每个 Agent **只负责一只股票**，任务如下：

1. 读取 `.tmp/{code}-weekly-data.json` 获取原始数据
2. 按以下维度进行周线级别分析：

| 维度 | 分析要点 | 量化指标 |
|------|----------|----------|
| KDJ 超卖程度 | K、D、J 值位置，是否 < 10 | 最新周 J 值 |
| 均线多头排列 | MA20 与 MA60 关系，斜率方向 | MA20 / MA60 比值、斜率 |
| 周线支撑 | 收盘价 vs 周 MA60 偏离度 | (收盘价 - 周MA60) / 周MA60 |
| 跨周期确认 | 日线 MA20 是否有效支撑 | 日线收盘价 vs 日MA20 偏离度 |
| 调整周期 | 自高点回落的周线数 | 调整周数 |
| 调整幅度 | 自高点回落的幅度 | (高点 - 最新价) / 高点 |

3. **基本面与行业分析**：

**3.1 财报硬伤检测**

从 `.tmp/{code}-weekly-data.json` 中提取财报数据，重点排查：

| 指标 | 风险阈值 |
|------|----------|
| 净利润同比 | 大幅下滑（>30%）为硬伤 |
| 经营现金流 | 连续为负为硬伤 |
| 资产负债率 | >70% 为硬伤 |
| 毛利率/净利率 | 同比连续走低预警 |
| ROE | 持续 <5% 预警 |

**3.2 行业发展情况**

通过 WebSearch / WebFetch 获取标的所属行业的发展情况，重点关注：

- **政策导向**：是否属于国家战略支持产业
- **行业增速**：行业营收/产能近 1-3 年复合增速
- **景气周期**：当前处于景气上行、景气高位、景气下行哪个阶段
- **竞争格局**：标的所处身位

> 检索关键词示例：`{行业名称} 2026 发展前景 政策 增速 龙头`

4. 按下方评分标准进行短线评分（周线趋势质量）和长线评分（基本面 + 行业）
5. 将分析结果保存到 `.tmp/{code}-weekly-analysis.json`，格式：

```json
{
  "code": "000001",
  "name": "平安银行",
  "short_score": 75,
  "short_reason": "周线KDJ J值8.5严重超卖，MA20>MA60多头排列，收盘站稳周MA60，日线MA20有效支撑",
  "long_score": 68,
  "long_reason": "净利润同比+12%，ROE 11%，负债率适中，银行业政策中性"
}
```

> 此阶段核心目标：**将分析工作负载分散到多个独立 Agent**，每个 Agent 只处理一只股票，分析更深入、上下文更干净。

### 阶段 4：汇总生成报告

1. 读取 `.tmp/` 下所有 `*-weekly-analysis.json` 文件
2. 按短线评分降序排列
3. 按下方模板生成标准化 Markdown 报告
4. 输出到 `./docs/analysis/weekly-b1/{日期}-周线B1分析.md`
5. 清理 `.tmp/` 临时文件（可选）

## 输出模板

```markdown
# {日期} 周线 B1 买点分析报告

## 分析概览

- 扫描日期：{日期}
- 分析模式：周线 B1 买点
- 信号股票总数：{N} 只
- 短线评分 ≥80 的优质标的：{M} 只
- 长线评分 ≥80 的优质标的：{K} 只

## 评分明细

| 股票名称 | 股票代码 | 周线J值 | 短线评分 | 短线原因 | 长线评分 | 长线原因 |
|----------|----------|---------|----------|----------|----------|----------|
| 平安银行 | 000001 | 8.5 | 75 | KDJ超卖，MA多头，支撑有效 | 68 | 净利润+12%，ROE 11% |

## 重点关注

**短线 + 长线双高（双 ≥80）**：列出推荐买入名单
**短线高但长线弱（短线 ≥80，长线 <70）**：列出适合短线博弈的名单
**长线高但短线弱（长线 ≥80，短线 <70）**：列出适合中线低吸的名单

## 风险提示

- 周线 B1 策略侧重中短线波段，需设好止损
- 周线级别信号频率低但可靠性相对较高
- KDJ 超卖不等于必然反弹，需结合均线和基本面综合判断
- 所有评分基于历史数据与公开信息，不构成投资建议
```

## 评分标准

评分体系分为**短线评分**（周线趋势质量）和**长线评分**（基本面 + 行业）两套独立体系，各满分 100 分。

### 一、短线评分（周线趋势质量，满分 100）

聚焦"周线 KDJ 超卖 + 均线多头排列 + 支撑确认"的质量。

#### 维度 A：KDJ 超卖程度（40 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| J 值位置 | 20 | J < 0 得 20；0-10 得 15；10-20 得 10；>20 得 0 |
| K、D 同步低位 | 10 | K < 20 且 D < 20 得 10；任一 >20 得 5；均 >30 得 0 |
| 超卖持续时间 | 10 | 超卖持续 ≥3 周得 10；1-2 周得 5；刚进入得 0 |

#### 维度 B：均线多头排列（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| MA20 > MA60 | 10 | MA20 在 MA60 之上且斜率向上得 10；在之上但走平得 5；下穿得 0 |
| 股价与 MA20 关系 | 10 | 收盘价 > MA20 得 10；回踩 MA20 得 5；跌破得 0 |
| 股价与 MA60 关系 | 10 | 收盘价 > MA60 得 10；回踩 MA60 得 5；跌破得 0 |

#### 维度 C：跨周期确认（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 日线 MA20 支撑 | 15 | 日线收盘价 > 日MA20 得 15；回踩不破得 8；跌破得 0 |
| 调整幅度 | 10 | 回调 ≤15% 得 10；15-25% 得 5；>25% 得 0 |
| 调整周期 | 5 | 调整 ≤8 周得 5；8-16 周得 3；>16 周得 0 |

### 二、长线评分（基本面 + 行业，满分 100）

与底部倍量模式共用同一套长线评分体系。

#### 维度 A：财报健康度（50 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 净利润同比 | 20 | ≥30% 得 20；10-30% 得 15；0-10% 得 8；下滑扣分（-30% 以下记 0） |
| 经营现金流 | 15 | 连续 4 期为正得 15；偶尔为正得 8；连续为负得 0 |
| 资产负债率 | 10 | ≤50% 得 10；50-70% 得 5；>70% 得 0 |
| 毛利率/ROE 趋势 | 5 | 稳健或上升得 5；微降得 3；显著下滑得 0 |

#### 维度 B：行业发展情况（50 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 政策导向 | 20 | 国家战略重点支持得 20；常规支持得 12；中性得 8；受限得 0 |
| 行业增速 | 15 | 复合增速 >15% 得 15；5-15% 得 10；持平得 5；负增长得 0 |
| 景气周期 | 10 | 景气上行得 10；高位得 6；下行得 0 |
| 竞争格局 | 5 | 标的为龙头/寡头得 5；前列得 3；分散竞争得 1 |

### 评级映射

| 分数段 | 评级 | 含义 |
|--------|------|------|
| 90-100 | S | 极佳 |
| 80-89 | A | 优秀 |
| 70-79 | B | 合格 |
| 60-69 | C | 勉强合格 |
| <60 | D | 不达标 |

## 数据持久化规范

| 阶段 | 文件路径 | 内容 | 责任人 |
|------|----------|------|--------|
| 信号列表 | `.tmp/weekly-b1-signals-{日期}.json` | 信号股票代码数组 + 扫描元数据 | 主会话 |
| 原始数据 | `.tmp/{code}-weekly-data.json` | 单只股票的周线 + 日线 + 财报原始数据 | 数据 Agent |
| 分析结果 | `.tmp/{code}-weekly-analysis.json` | 单只股票的评分和分析摘要 | 分析 Agent |

> `.tmp/` 为临时目录，分析完成后由主会话统一清理。

## 注意事项

1. **Agent 分治原则**：
   - **数据获取 Agent**：每批 5-10 只股票，只负责调 API + 写文件，不做分析
   - **个股分析 Agent**：每只一个 Agent，只读取 `.tmp/{code}-weekly-data.json` + 写 `.tmp/{code}-weekly-analysis.json`
   - **主会话**：只负责启动 Agent、汇总结果、生成报告
   - **严禁在主会话中堆积原始 JSON 数据**

2. **并行执行**：
   - 阶段 2（数据获取）：按批次启动并行 agent，每批 5-10 只
   - 阶段 3（个股分析）：每只一个独立 agent，可高度并行
   - 阶段 2 完成后才能启动阶段 3（依赖关系）

3. **周线数据特点**：
   - 周线 K 线数据建议 `pagesize=20`（约 5 个月）
   - 日线 K 线数据建议 `pagesize=60`（约 3 个月），用于跨周期 MA20 验证
   - 周线信号频率远低于日线，扫描结果通常 10-30 只

4. **数据缺失**：如某只股票缺失周线或日线数据，在 `.tmp/{code}-weekly-analysis.json` 中标注"数据缺失"

5. **评分客观**：评分需有明确周线级别量价依据，原因描述具体

6. **增量分析**：如果 `./docs/analysis/weekly-b1/` 下已有同日期报告，询问用户是否覆盖
