# 底部倍量拉升 + 缩量回调分析流程

> 本文档指导如何执行"底部倍量拉升后缩量回调"策略扫描与个股分析。执行前请先阅读 `api_reference.md` 了解 API 速查表。
>
> **在开始任何个股分析之前，必须先阅读 `assets/` 目录下的 4 张示例图，建立形态识别的视觉锚点**：
> - `assets/豪迈科技.png` — 单根超量大阳线启动 + 高位平台整理
> - `assets/潍柴动力.png` — 单日超 5 倍量启动 + 长期横盘震荡
> - `assets/亨通光电.png` — 阶梯式连续放量推升 + 缓慢横盘整理
> - `assets/中天科技.png` — V 型反转 + 温和放量 + 浅幅回调

## 核心逻辑

该策略基于量价关系识别**主力吸筹**信号，分四阶段确认：

1. **底部确认**：价格处于近期低位，均线粘合或多头未发散，排除追高
2. **倍量启动**：成交量骤增（单日 ≥ 2 倍均量或连续 3-5 日维持 1.5 倍量），配合实体大阳线，代表主力大幅进场
3. **缩量回调/横盘**：拉升后成交量快速萎缩（≤ 拉升期峰值 30-50%），价格小幅回落或窄幅震荡
4. **主力锁仓**：整理期间无放量阴线、不破 MA20，说明筹码被锁定，没有出货

## 形态变体识别（基于 assets 示例图）

实战中存在三种典型变体，需根据启动节奏和整理形态区分匹配：

| 变体类型 | 启动特征 | 拉升幅度 | 整理形态 | 整理时长 | 参考图 |
|---------|---------|---------|----------|----------|--------|
| **单日超量启动型** | 1 根 ≥ 5 倍均量大阳线打开空间 | 5-10 天累计 15-40% | 高位平台或宽幅震荡 | 20-40 天 | 潍柴动力、豪迈科技 |
| **阶梯放量推升型** | 连续 5-10 日放量阳线阶梯推升 | 10-20 天累计 30-50% | 缓慢横盘或斜上整理 | 15-30 天 | 亨通光电 |
| **V 型反转型** | 温和持续放量，无单日异常巨量 | 10-15 天累计 20-30% | 浅幅回调后站稳 MA20 | 10-20 天 | 中天科技 |

## 关键量价特征（统一筛选条件）

### A. 底部确认信号
- 价格在前期低位窄幅震荡 ≥ 15 个交易日
- 均线粘合：MA5、MA20、MA60 在 ±3% 范围内缠绕，或处于走平状态
- 形成明确的近期最低点（K 线图上可见的"底"）

### B. 启动信号（放量拉升）
- **量能突变**：单日量 ≥ 5 日均量的 2 倍，理想情况 5 倍以上
- **阳线主导**：拉升期阳线实体占比 ≥ 70%，收盘价接近最高价（无明显上影线）
- **斜率陡峭**：MA5 由下转上、斜率显著陡于 MA20
- **突破有效**：单日或区间高点突破前期密集成交区或 MA60 等关键阻力

### C. 缩量回调/横盘信号
- **缩量充分**：回调期 5 日均量 ≤ 拉升期峰值量的 30-50%
- **深度可控**：自拉升高点回调 5-15%（最深不超 20%）
- **支撑明确**：站稳 MA20，或回踩 MA20 后迅速收回
- **无主力出货**：整理期间不出现 ≥ 拉升日量能的放量阴线
- **红绿柱均衡**：阴阳交替，单日波动幅度 < 拉升期日均波幅

### D. 均线多头排列
- 启动后 MA5 > MA20 > MA60，多头排列确认
- MA20 由平转向上，斜率持续为正
- 价格主要运行在 MA20 上方，整理期不有效跌破

### E. 筹码锁定确认
- 整理期成交量呈持续萎缩趋势（"地量"特征）
- 阴线带量 < 阳线带量（抛压弱于承接）
- 横盘越久、缩量越彻底，后续突破弹性越大

> 经典案例：中天科技（2026年1月底、4月中下旬）、豪迈科技（2025年10月底、12月初）

## 执行步骤

### 阶段 1：获取并持久化信号列表

调用 `/api/stocks/signal` 获取底部倍量回调信号股票列表，**将结果保存到文件**。

```bash
curl "http://192.168.31.85:38687/api/stocks/signal?strategy=bottom_surge_pullback"
```

保存到 `.tmp/bottom-surge-signals-{日期}.json`：

```json
{
  "date": "2026-05-25",
  "strategy": "bottom_surge_pullback",
  "codes": ["601991", "000042", "000651", "000802", ...],
  "total": 49
}
```

> 接口完整文档见 `api_reference.md`。扫描耗时较长，建议超时 **60s**。

### 阶段 2：批量获取股票数据（并行 Agent）

**启动多个并行 Agent**，每个 Agent 负责一批股票（建议每批 **5-10 只**），任务如下：

1. 读取 `.tmp/bottom-surge-signals-{日期}.json`，获取分配到的股票代码
2. 对每只股票调用 API 获取：
   - **K 线数据**：`/api/stocks/price?code={code}&cycle=daily&pagesize=60`
   - **财报数据**：`/api/stocks/financial-report?code={code}&pagesize=20`
3. 将原始数据保存到 `.tmp/{code}-data.json`，格式：

```json
{
  "code": "688581",
  "name": "安杰思",
  "price": { "data": [...] },
  "financial": { "data": [...] }
}
```

> 此阶段核心目标：**将原始数据持久化到文件**，避免在主会话上下文中堆积大量 JSON。

### 阶段 3：个股量价与基本面分析（并行 Agent）

**启动多个并行 Agent**，每个 Agent **只负责一只股票**，任务如下：

1. 读取 `.tmp/{code}-data.json` 获取原始数据
2. **对照 `assets/` 下的四张示例图**，识别形态变体
3. 按以下维度进行量价分析：

| 维度 | 分析要点 | 量化指标 |
|------|----------|----------|
| 形态变体识别 | 单日超量型 / 阶梯推升型 / V 型反转型 | 参照 `assets/*.png` 视觉锚点 |
| 拉升强度 | 倍量天数、连阳天数、最大涨幅 | 最大单日量比、累计涨幅 % |
| 缩量程度 | 回调期均量 / 拉升期峰值量 | 缩量率 = 1 - 回调期均量/峰值量 |
| 回调深度 | (峰值 - 最新价) / 峰值 | 回调幅度 % |
| 支撑强度 | 是否守住 MA20 / 前低 | 收盘价 vs MA20 偏离度 |
| 筹码锁定 | 缩量期间是否有异常放量阴线 | 整理期最大阴线量 vs 拉升日量 |
| 整理时长 | 自高点至今的交易日数 | 整理天数 |

4. **基本面分析**（仅基于本地财报数据）：

从 `.tmp/{code}-data.json` 中提取财报数据，从以下四个维度进行综合评估：

| 维度 | 指标 | 风险阈值 / 评分要点 |
|------|------|---------------------|
| 盈利增长 | 净利润同比 | 大幅下滑（>30%）为硬伤 |
| 盈利增长 | 营收同比 | 连续下滑预警 |
| 盈利质量 | 经营现金流 | 连续为负为硬伤 |
| 盈利质量 | 毛利率趋势 | 同比连续走低预警 |
| 盈利质量 | ROE | 持续 <5% 预警 |
| 财务安全 | 资产负债率 | >70% 为硬伤 |
| 财务安全 | 流动比率 | <1 预警 |
| 运营效率 | 总资产周转率 | 持续走低预警 |
| 运营效率 | EPS 趋势 | 连续下滑预警 |

> **严禁使用 WebSearch / WebFetch 搜索行业或基本面信息**。长线评分完全基于本地财报 API 返回的数据。

5. **行业标注**：根据股票名称/代码推断其所属行业，在分析结果中标注（仅标注，不参与评分）

6. 按本文档"评分标准"章节进行短线评分和长线评分
7. 将分析结果保存到 `.tmp/{code}-analysis.json`，格式：

```json
{
  "code": "688581",
  "name": "安杰思",
  "industry": "医疗器械",
  "variant": "单日超量启动型",
  "short_score": 72,
  "short_reason": "单日 10x 巨量，3 连阳，缩量 86%，回调 17.4% 偏深",
  "long_score": 73,
  "long_reason": "毛利率 70%+，负债率仅 6%，现金流健康，但净利润增速放缓至 7.6%"
}
```

> 此阶段核心目标：**将分析工作负载分散到多个独立 Agent**，每个 Agent 只处理一只股票，分析更深入、上下文更干净。每个 Agent 独立计算 MA、量比、涨幅、缩量率等量化指标。

### 阶段 4：汇总生成报告

1. 读取 `.tmp/` 下所有 `*-analysis.json` 文件
2. 按短线评分降序排列
3. 按下方模板生成标准化 Markdown 报告
4. 输出到 `./docs/analysis/bottom-surge/{日期}-底部倍量分析.md`
5. 清理 `.tmp/` 临时文件（可选）

## 评分标准

评分体系分为**短线评分**和**长线评分**两套独立体系，各满分 100 分。

### 一、短线评分（量价形态，满分 100）

聚焦"放量拉升 + 缩量回调"的量价质量，越符合主力吸筹特征评分越高。

#### 维度 A：放量拉升强度（50 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 单日最大量比 | 20 | ≥5.0x 得 20；3.0-5.0x 得 15；2.0-3.0x 得 10；<2.0x 得 0 |
| 拉升累计涨幅 | 15 | 5-10 日内 ≥30% 得 15；20-30% 得 10；10-20% 得 5；<10% 得 0 |
| 连阳天数 | 10 | ≥3 天得 10；2 天得 5；1 天得 0 |
| 大阳线占比 | 5 | 拉升期阳线实体占比 ≥70% 得 5；50-70% 得 3；<50% 得 0 |

#### 维度 B：缩量回调质量（50 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 缩量率 | 20 | ≥70% 得 20；50-70% 得 15；30-50% 得 10；<30% 得 0 |
| 回调深度 | 15 | ≤5% 得 15；5-10% 得 10；10-15% 得 5；>15% 得 0 |
| MA20 支撑 | 10 | 站稳 MA20 得 10；回踩不破得 5；有效跌破得 0 |
| 整理纯净度 | 5 | 整理期无 ≥拉升日量的放量阴线得 5；有则得 0 |

### 二、长线评分（财报基本面，满分 100）

聚焦标的的中长期投资价值，完全基于本地财报 API 数据评估，**不依赖任何网上搜索**。

#### 维度 A：盈利增长（30 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 净利润同比 | 20 | ≥30% 得 20；10-30% 得 15；0-10% 得 8；下滑扣分（-30% 以下记 0） |
| 营收同比 | 10 | ≥20% 得 10；5-20% 得 7；0-5% 得 4；下滑（<0）记 0 |

#### 维度 B：盈利质量（25 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 经营现金流 | 15 | 连续 4 期为正得 15；偶尔为正得 8；连续为负得 0 |
| 毛利率趋势 | 5 | 稳健或上升得 5；微降得 3；显著下滑得 0 |
| ROE 水平 | 5 | ≥15% 得 5；5-15% 得 3；<5% 得 0 |

#### 维度 C：财务安全（25 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 资产负债率 | 10 | ≤50% 得 10；50-70% 得 5；>70% 得 0 |
| 流动比率 | 8 | ≥2.0 得 8；1.0-2.0 得 5；<1.0 得 0 |
| 速动比率 | 7 | ≥1.0 得 7；0.5-1.0 得 4；<0.5 得 0 |

#### 维度 D：运营效率（20 分）

| 子项 | 满分 | 评分标准 |
|------|------|----------|
| 总资产周转率趋势 | 8 | 稳健或上升得 8；微降得 5；显著下滑得 0 |
| EPS 增长趋势 | 7 | 连续增长得 7；持平得 4；连续下滑得 0 |
| 扣非净利润占比 | 5 | 扣非/归母 ≥90% 得 5；70-90% 得 3；<70% 得 0 |

### 评级映射

| 分数段 | 评级 | 含义 |
|--------|------|------|
| 90-100 | S | 极佳 |
| 80-89 | A | 优秀 |
| 70-79 | B | 合格 |
| 60-69 | C | 勉强合格 |
| <60 | D | 不达标 |

## 数据持久化规范

| 阶段 | 文件路径 | 内容 | 责任人 |
|------|----------|------|--------|
| 信号列表 | `.tmp/bottom-surge-signals-{日期}.json` | 信号股票代码数组 + 扫描元数据 | 主会话 |
| 原始数据 | `.tmp/{code}-data.json` | 单只股票的 K 线 + 财报原始数据 | 数据 Agent |
| 分析结果 | `.tmp/{code}-analysis.json` | 单只股票的评分和分析摘要 | 分析 Agent |

> `.tmp/` 为临时目录，分析完成后由主会话统一清理。如需保留原始数据供后续复盘，可移至 `data/raw/`。

## 注意事项

1. **Agent 分治原则**：
   - **数据获取 Agent**：每批 5-10 只股票，只负责调 API + 写文件，不做分析
   - **个股分析 Agent**：每只一个 Agent，只读取 `.tmp/{code}-data.json` + 写 `.tmp/{code}-analysis.json`
   - **主会话**：只负责启动 Agent、汇总结果、生成报告
   - **严禁在主会话中堆积原始 JSON 数据**——所有 API 返回的原始数据必须立即持久化到 `.tmp/` 文件

2. **并行执行**：
   - 阶段 2（数据获取）：按批次启动并行 agent，每批 5-10 只
   - 阶段 3（个股分析）：每只一个独立 agent，可高度并行
   - 阶段 2 完成后才能启动阶段 3（依赖关系）

3. **超时设置**：
   - `/api/stocks/signal` 扫描数据库耗时较长，建议超时 **60s**
   - `/api/stocks/price` 和 `/api/stocks/financial-report` 建议超时 **30s**

4. **数据缺失**：如某只股票缺失 K 线或财报数据，在 `.tmp/{code}-analysis.json` 中标注"数据缺失"，不影响其他股票分析

5. **评分客观**：评分需有明确量价依据，原因描述具体。每个分析 Agent 独立计算量化指标（MA、量比、涨幅、缩量率等），避免依赖主会话中的全局状态

6. **增量分析**：如果 `./docs/analysis/bottom-surge/` 下已有同日期报告，询问用户是否覆盖
