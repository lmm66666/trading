# 底部倍量拉升 + 缩量回调分析流程

> 本文档指导如何执行"底部倍量拉升后缩量回调"策略扫描与个股分析。执行前请先阅读 `api_reference.md` 了解 API 速查表。

## 核心逻辑

该策略基于量价关系识别**主力吸筹**信号：

1. **底部确认**：价格处于近期低位，排除追高
2. **倍量拉升**：成交量骤增（≥2倍均量），配合大阳线（≥5%），代表主力大幅进场
3. **缩量回调**：拉升后成交量快速萎缩（≤拉升期50%），价格小幅回落
4. **主力锁仓**：缩量回调说明筹码被锁定，没有出货

> 经典案例：中天科技（2026年1月底、4月中下旬）、豪迈科技（2025年10月底、12月初）

## 执行步骤

### 步骤 1：获取信号股票

调用 `/api/stocks/signal` 获取处于底部倍量回调状态的股票代码列表。

```bash
curl "http://192.168.31.85:41027/api/stocks/signal?strategy=bottom_surge_pullback"
```

策略名称：`bottom_surge_pullback`

> 接口完整文档见 `api_reference.md`。

### 步骤 2：获取股票数据

对每只信号股票并行获取：
- **股价 K 线数据**：调用 `/api/stocks/price?cycle=daily&pagesize=60`
- **财报数据**：调用 `/api/stocks/financial-report?pagesize=20`

### 步骤 3：个股量价分析

对每只信号股票进行量价特征分析：

| 维度 | 分析要点 |
|------|----------|
| 拉升强度 | 倍量天数、连阳天数、最大涨幅 |
| 缩量程度 | 回调期均量 / 拉升期均量 |
| 回调深度 | (峰值 - 最新价) / 峰值 |
| 支撑强度 | 是否守住 MA20 / 前低 |
| 筹码锁定 | 缩量期间是否有异常放量 |

### 步骤 4：基本面过滤

结合财报数据排除基本面恶化的标的：
- 净利润同比大幅下滑（>30%）标注风险
- 经营现金流为负标注风险
- 资产负债率 > 70% 标注风险

### 步骤 5：输出报告

生成标准化 markdown 报告，输出到 `./docs/analysis/bottom-surge/`。

文件名格式：`{日期}-底部倍量分析.md`

## 输出模板

```markdown
# {日期} 底部倍量拉升分析报告

## 分析概览

- 扫描日期：{日期}
- 分析模式：底部倍量回调
- 信号股票总数：{N} 只
- 量价评分 ≥80 的优质标的：{M} 只

## 评分明细

| 股票名称 | 股票代码 | 拉升量比 | 缩量率 | 回调深度 | 支撑状态 | 综合评分 | 原因 |
|----------|----------|----------|--------|----------|----------|----------|------|
| 中天科技 | 600522 | 2.14 | 55% | 5% | 站稳MA20 | 88 | 倍量拉升后缩量整理，筹码锁定良好 |
| 豪迈科技 | 002595 | 3.21 | 70% | 4% | 站稳MA20 | 92 | 连续两天倍量，缩量极快，控盘极强 |

## 重点关注（综合评分 ≥80）

列出评分在 80 分以上的股票，说明推荐理由。

## 风险提示

- 底部倍量策略侧重中短线，需设好止损
- 所有评分基于历史数据，不构成投资建议
- 需结合大盘环境判断，系统性风险下所有形态可能失效
- 放量拉升可能是游资短炒，需结合基本面排除
```

## 评分标准

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 拉升强度 | 25% | 量比≥3.0得25分，2.5-3.0得20分，2.0-2.5得15分 |
| 缩量程度 | 25% | 缩量率≥70%得25分，50-70%得20分，30-50%得10分 |
| 回调深度 | 20% | 回调≤5%得20分，5-10%得15分，10-15%得10分 |
| 支撑状态 | 15% | 站稳MA20得15分，回踩MA20得10分，跌破不得分 |
| 基本面 | 15% | 净利润增长+现金流正得15分，有瑕疵酌情扣分 |

## 注意事项

1. **并行执行**：获取多只股票数据时，使用并行 agent 加速
2. **超时设置**：`/api/stocks/signal` 扫描数据库耗时较长，建议超时 60s
3. **数据缺失**：如某只股票缺失 K 线数据，在报告中标注"数据缺失"
4. **评分客观**：评分需有明确量价依据，原因描述具体
5. **增量分析**：如果 `./docs/analysis/bottom-surge/` 下已有同日期报告，询问用户是否覆盖
